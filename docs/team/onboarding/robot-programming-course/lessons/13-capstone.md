# 13 · Own a subsystem

Requires gate C. Finish without copying a step-by-step solution.

Work in small steps. For each checkpoint, copy templates/SUBMISSION.md into your named submission folder. Include a source snapshot, exact commands, evidence, and answers. Do not overwrite an earlier attempt.

## Checkpoint A — Plan a new requirement

**Learn:** Independent work starts with a contract and tests, not random changes.

**Do:** Choose one: three named scoring presets plus a safe manual override; a new elevator mass/gearing; or an arm/flywheel extension with an appropriate WPILib model. State inputs, outputs, units, states, measurable success criteria, and at least five tests before implementation.

**Submit:** A one-page plan accepted by the mentor. Robot access is optional.

**Explain:** Which tests check understanding rather than only the happy path?

## Checkpoint B — Build and submit

**Learn:** The source and evidence should describe exactly the same version.

**Do:** Implement, simulate, measure, and fix. Submit a clean project snapshot or commit, setup instructions, model card, logs/graphs, test output, known limitations, and a completed acceptance table. Keep a list of help used.

**Submit:** Complete reproducible subsystem submission.

**Explain:** What result would make you reject your own implementation?

## Checkpoint C — Explain and adapt

**Learn:** Understanding transfers to a small unfamiliar change.

**Do:** Demonstrate the subsystem in simulation. Mentor chooses a small new change such as a new target, revised tolerance, or reversed encoder sign. Predict the effect, locate the code, make the change, rerun a relevant test, and explain the result.

**Submit:** Mentor feedback, final revision, and completion record. This is the same assessment with or without a real robot.

**Explain:** What can simulation establish, and what remains unknown without physical testing?

## Ready to move on

You can reproduce your result from a clean start and explain it without reading a solution. Mark the submission ready-for-review. If feedback requests a change, create another attempt and describe what you learned.
