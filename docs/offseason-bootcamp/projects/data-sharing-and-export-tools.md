# Data Sharing and Export Tools

## Summary

Improve how logs and analysis data are exported, shared, and reviewed so students and mentors can collaborate more easily after tests, practices, and events.

## Why This Project Matters

- Better access to logs makes debugging faster.
- Students can review data asynchronously instead of waiting on one mentor.
- Stronger export workflows make retrospective analysis easier.

## Proposed Approach

1. Map the current logging workflow from robot run to log review.
2. Identify friction points, such as manual copying, unclear file naming, missing exports, or hard-to-share formats.
3. Define the minimum useful output for students and mentors.
4. Prototype a better export flow, viewer, dashboard, or packaging format.
5. Test whether a student can retrieve and use the exported data without software mentor intervention.

## Deliverables

- A documented log-sharing workflow.
- A lightweight tool, script, viewer concept, or process improvement proposal.
- A clear recommendation on what should be automated next.

## Competency Checklist

- Can explain where logs come from and how they are currently reviewed.
- Can inspect file formats and basic data structure without getting lost.
- Can identify user pain points, not just technical pain points.
- Can document a process clearly enough for drive team or students to follow.
- Can propose validation criteria for whether the new workflow is actually better.

## Good Stretch Goals

- Standardize naming or metadata for exported log bundles.
- Create a simple status checklist for post-match data handling.
- Make the workflow friendly for non-programmers.
