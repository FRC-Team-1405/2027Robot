# Offseason Programming Boot Camp

This folder turns the mentor retro notes into a structure that can be used to run an offseason programming boot camp before students move into actual offseason project execution.

## High-Level Goal

Build student programming fundamentals first, rebuild good robot-software habits second, and only then transition students into larger offseason projects.

## Why This Boot Camp Exists

- Current software students have put in real effort, but some still need reinforcement on basic programming ideas such as classes, methods, object responsibilities, and code organization.
- Students need more repetition on robot-specific software patterns, especially subsystem structure, command wiring, logging, debugging, and best practices.
- The team should use the fall to move from training into project execution instead of asking students to jump directly into deep technical work without a stronger foundation.
- The program likely needs two tracks so new students and returning students can both be challenged appropriately.

## Boot Camp Structure

1. Foundations phase
   - Focus on programming basics and code reading.
   - Teach how robot code is organized.
   - Reinforce naming, classes, methods, state, and debugging habits.
2. Robot-code phase
   - Move into subsystem patterns, commands, logging, simulation, and sensors.
   - Practice making small changes safely in a robot codebase.
3. Track split phase
   - Beginner track continues building Programming 101 skills using robot examples.
   - Advanced track rebuilds the existing robot code architecture from scratch in a guided way.
4. Project transition phase
   - Students move into offseason projects only after they show the needed competency for the work.

## Notes Captured From the Mentor Retro

- Boot camp should happen before major offseason project execution.
- There should be a rough overall outline plus module-level planning for new students.
- Student placement may need to vary depending on who joins and what skills they already have.
- Advanced students should work toward rebuilding the existing robot code from scratch rather than only making isolated edits.
- Best-practice documentation should be updated and expanded, especially around logging expectations and competition lessons learned.
- Mentor and company volunteer support should be identified early if two student tracks will run in parallel.
